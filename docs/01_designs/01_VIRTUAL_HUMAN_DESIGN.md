## 1. VH Agent 概述

### 核心職責

Virtual Human Agent 專注於**對話、陪伴、客服**場景，提供：

- ✅ **情感化回應** - 有溫度、有個性
- ✅ **快速互動** - 安撫話語 < 1 秒
- ✅ **知識支撐** - RAG 檢索準確回答
- ✅ **風格一致** - Persona 綁定獨特個性

### 與 BO Agent 的區別

| 維度 | VH Agent | BO Agent |
|------|---------|---------|
| **用途** | 對話、陪伴、客服 | 後台管理、配置維護 |
| **用戶** | 一般用戶 | 管理員、開發者 |
| **風格** | 情感化、個性化 | 專業、直接 |
| **架構** | 雙 LLM（快速 + 完整） | 單 Agent Loop（多輪） |

## 2. VH Agent 架構

### 2.1 雙 LLM 架構

**核心特點：**
- **LLM1** - 負責快速回應 + RAG 判斷（2-5 秒）
- **LLM2** - 負責完整回答（10-30 秒）
- **快速發送** - 安撫話語 < 100ms 發送

**工作流程：**
```
用戶輸入
   │
   ▼
┌─────────────────┐
│ LLM1 判斷        │ ⏱️ 2-5 秒
│ - 是否需要 RAG   │
│ - 生成安撫話語   │
└─────────────────┘
   │
   ▼
⚡ 立即發送安撫話語  ← 關鍵！< 100ms
   │
   ▼ (串行)
┌─────────────────┐
│ 載入相關文件     │
│ (如果需要)       │
└─────────────────┘
   │
   ▼
┌─────────────────┐
│ LLM2 生成回答    │
│ - 完整內容       │
│ - emotion/lang   │
└─────────────────┘
   │
   ▼
返回完整回答
```

### 2.2 RAG 兩階段檢索

**階段 1：Meta 判斷**
- 讀取 `meta.json`（小文件）
- LLM 判斷相關文件
- 節省 Token

**階段 2：文件載入**
- 只載入相關文件
- 完整內容檢索
- 準確回答

### 2.3 STREAM 模式

**特點：**
- 分段發送回答
- 支持 `emotion`/`lang` 標籤
- 提升用戶體驗

**SSE 事件：**
```javascript
{
  type: "stream_start",
  // ...
}

{
  type: "text_chunk",
  text: "...",
  is_comforting: true
}

{
  type: "done",
  emotion: "happy",
  lang: "zh-TW"
}
```

                            │

│    - 判斷需要 RAG（knowledge_ids: ["ubitus"]）          │

└─────────────────────────────────────────────────────────┘
                            │
                            ▼
                    ⚡ 立即發送安撫話語
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 3. KNOWLEDGE - 載入相關文件                              │
│    - products.txt                                       │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 4. PERSONA - 載入風格 Prompt                             │
│    - 親切、活潑語氣                                     │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 5. VH AGENT - LLM2 生成完整回答                          │

│    - 保存用戶輸入                                        │

│ 7. 前端 - 顯示回答                                       │
│    - STREAM 分段顯示                                     │
│    - 應用 emotion/lang 樣式                              │

## 4. VH 設計決策

### 4.1 為什麼採用雙 LLM 架構？

**問題：** 單一 LLM 生成完整回答需要 10-30 秒，用戶體驗差。

**解決方案：** 雙 LLM 架構
- LLM1 專門生成安撫話語（2-5 秒）
- LLM2 專門生成完整回答（10-30 秒）
- 安撫話語立即發送，提升用戶體驗

**權衡：**
- ✅ 優點：用戶體驗大幅提升
- ⚠️ 缺點：增加 LLM 呼叫成本（2 次 vs 1 次）

### 4.2 為什麼採用兩階段 RAG？

**問題：** 直接載入所有文件會消耗大量 Token，增加延遲。

**解決方案：** 兩階段檢索
- 階段 1：只讀取 `meta.json`（小文件），LLM 判斷相關文件
- 階段 2：只載入相關文件的完整內容

**權衡：**
- ✅ 優點：節省 Token，提高檢索準確性
- ⚠️ 缺點：增加一次 LLM 呼叫（Meta 判斷）

### 4.3 為什麼需要 Persona？

**問題：** 通用 LLM 回應缺乏個性，無法建立情感連結。

**解決方案：** Persona 系統
- 定義角色個性、說話風格
- 綁定 Session，保持一致性
- 支持多角色切換
- 配置快速回應長度（`quick_response.max_length`）

### 4.4 Persona 配置項目

**v2.1 新增：**
- `quick_response.max_length` - 快速回應最大長度（字）
- `output_format` - 支援 3 種格式（virtual_human, plain, markdown）

**配置範例：**
```yaml
persona_id: ubichan
display_name: 優必醬

output_format: plain

quick_response:
  max_length: 20  # 預設 20 字

knowledge:
  enabled: true
  folders:
    - ubitus/
```
