## 1. BO Agent 概述

### 核心職責

Backend Operator 專注於**後台管理、知識庫維護、配置修改**場景，提供：

- ✅ **專業執行** - 準確完成管理任務
- ✅ **多輪協作** - 複雜任務多輪執行
- ✅ **透明進度** - 實時回報執行狀態
- ✅ **安全機制** - 敏感操作需授權

### 與 VH Agent 的區別

| 維度 | BO Agent | VH Agent |
|------|---------|---------|
| **用途** | 後台管理、配置維護 | 對話、陪伴、客服 |
| **用戶** | 管理員、開發者 | 一般用戶 |
| **風格** | 專業、直接 | 情感化、個性化 |
| **架構** | 單 Agent Loop（多輪） | 雙 LLM（快速 + 完整） |
| **Tool 使用** | 較多（文件操作） | 較少（知識庫查詢） |

## 2. BO Agent 架構

### 2.1 Agent Loop 多輪執行

**核心特點：**
- **多輪循環** - 支持最多 10 輪執行
- **Tool 驅動** - 自動判斷並調用 Tool
- **實時進度** - 每輪回報執行狀態

**工作流程：**
```
用戶輸入
   │
   ▼
┌─────────────────────────────────────┐
│ Round 1                              │
│ - 解析用戶指令                       │
│ - 判斷需要執行的 Tool                │
│ - 執行 Tool                          │
│ - 判斷是否繼續                       │
└─────────────────────────────────────┘
   │
   ▼ (繼續？)
┌─────────────────────────────────────┐
│ Round 2                              │
│ - 基於 Round 1 結果繼續               │
│ - 執行下一個 Tool                    │
│ - ...                                │
└─────────────────────────────────────┘
   │
   ▼ (完成？)
┌─────────────────────────────────────┐
│ 最終回應                             │
│ - 整合所有執行結果                   │
│ - 生成完整報告                       │
└─────────────────────────────────────┘
```

### 2.2 雙指標決策系統

**指標 1：AGENT 還要繼續**

| 值 | 說明 | 系統行為 |
|----|------|---------|
| **YES** | Agent 有主動下一步 | 繼續循環 |
| **NO** | 需要用戶介入或已完成 | 停止循環 |

**指標 2：用戶指令完成**

| 值 | 說明 | 系統行為 |
|----|------|---------|
| **YES** | 用戶目標已達成 | 生成成功回應 |
| **NO** | 還需要用戶輸入 | 生成詢問回應 |

**決策矩陣：**
```
AGENT 還要繼續 = YES  → 繼續循環
AGENT 還要繼續 = NO + 用戶指令完成 = YES  → 成功完成
AGENT 還要繼續 = NO + 用戶指令完成 = NO   → 需要用戶介入
```

### 2.3 三類執行狀態

```python
class ExecutionStatus(Enum):
    DONE = "done"                        # 用戶目標完成
    NEEDS_INTERACTION = "needs_input"    # 需要用戶介入
    ERROR = "error"                      # 執行異常
```

**狀態說明：**

| 狀態 | 觸發條件 | 回應方式 |
|------|---------|---------|
| **DONE** | 用戶指令完成 | 整合結果，生成報告 |
| **NEEDS_INTERACTION** | 需要用戶輸入/確認 | 詢問用戶，等待回應 |
| **ERROR** | Tool 失敗/超輪數 | 解釋問題，提供已有結果 |

## 2.4 BO 可用 Tool 列表

目前 BO Agent 支援 **11 個 Tool**，分為 4 大類：

### 文件操作類（4 個）

| Tool 名稱 | 功能 | 使用場景 |
|-----------|------|----------|
| `read_file` | 讀取文本文件 | 查看配置文件、日誌、文檔 |
| `write_file` | 寫入文件 | 創建/修改配置文件、腳本 |
| `list_dir` | 列出目錄內容 | 查看文件結構、確認文件存在 |
| `read_excel` | 讀取 Excel (.xlsx) | 讀取報表、數據分析 |

### 知識庫類（3 個）

| Tool 名稱 | 功能 | 使用場景 |
|-----------|------|----------|
| `knowledge_meta` | 查詢知識庫 Meta | 查看知識庫文件索引 |
| `knowledge_query` | 查詢知識庫內容 | 檢索專業知識、回答問題 |
| `rebuild_knowledge_meta` | 重建知識庫 Meta | 知識庫更新後重新生成索引 |

### 其他文件格式（3 個）

| Tool 名稱 | 功能 | 使用場景 |
|-----------|------|----------|
| `read_csv` | 讀取 CSV 文件 | 讀取數據導出、表格數據 |
| `read_word` | 讀取 Word (.docx) | 讀取報告、辦公文檔 |
| `read_pdf` | 讀取 PDF 文件 | 讀取技術文檔、掃描文件 |

### 網路類（1 個）

| Tool 名稱 | 功能 | 使用場景 |
|-----------|------|----------|
| `web_search` | 網路搜尋 | 查詢即時資訊、新聞 |

---

### Tool 使用原則

1. **主動調用** - 當用戶問題涉及文件操作時，主動調用 Tool
2. **不重複執行** - 已成功執行的 Tool 不重複調用
3. **錯誤處理** - Tool 失敗時直接停止，不重試

### 實現位置

所有 Tool 在 `agent/backend_operator/api.py` 中註冊：

```python
TOOL_INSTANCES = {
    "read_file": read_tool,
    "write_file": write_tool,
    "list_dir": list_tool,
    "read_excel": excel_tool,
    "read_csv": csv_tool,
    "read_word": word_tool,
    "read_pdf": pdf_tool,
    "knowledge_meta": meta_tool,
    "knowledge_query": query_tool,
    "rebuild_knowledge_meta": gen_tool,
    "web_search": search_tool,
}
```

**已移除：** `scan_workspace` - 改用基本 Tool 代替

## 4. BO 設計決策

### 4.1 為什麼採用多輪 Agent Loop？

**問題：** 複雜管理任務需要多步驟執行，單一 LLM 呼叫無法完成。

**解決方案：** Agent Loop 多輪執行
- 每輪執行一個或多個 Tool
- 基於結果判斷是否繼續
- 支持最多 10 輪循環

**權衡：**
- ✅ 優點：支持複雜任務、透明進度
- ⚠️ 缺點：執行時間較長

### 4.2 為什麼需要雙指標系統？

**問題：** 單一「完成」標誌無法區分「成功完成」和「需要用戶介入」。

**解決方案：** 雙指標系統
- `AGENT 還要繼續` - 控制循環
- `用戶指令完成` - 判斷任務狀態

**權衡：**
- ✅ 優點：清晰區分三種狀態
- ⚠️ 缺點：LLM 需要理解兩個指標

### 4.3 為什麼限制 10 輪？

**問題：** 無限循環可能導致資源浪費。

**解決方案：** 強制限制
- 最多 10 輪執行
- 超輪數 → ERROR 狀態

**權衡：**
- ✅ 優點：防止無限循環
- ⚠️ 缺點：極複雜任務可能無法完成
